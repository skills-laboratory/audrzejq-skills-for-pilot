# Boeing 737 descent and approach preparation

## Prepare and record independent items

- Read actual altitude, IAS, vertical speed, configuration, FMA, and distance to the approach. Preserve functioning automation while preparing; an ALT HOLD label or selected altitude does not prove level flight at that target. Estimate minutes to the intercept as 60 times remaining NM divided by groundspeed in kt. If preparation will not finish in that distance, execute and verify an authorized level-off, vector, or hold within chart/clearance constraints rather than continuing toward the runway unprepared; level flight alone does not preserve the distance needed for preparation.
- Read the selected approach chart, live descent/approach checklists, landing continuation, and missed approach before intercept. Identify runway, ILS frequency/identifier, magnetic course, distance source, segment altitudes, minima datum, and missed-approach track/altitude. Different DME stations and threshold distance are not interchangeable; obtain the chart's required reference rather than assuming the ILS DME matches it.
- Set local QNH with the correct pressure units and verify the required altimeters and pressure-reference modes. Set pressurization landing altitude from the destination elevation, not the decision height; perform the prescribed annunciator recall and resolve actual warnings.
- For BARO minimums, enter the published DA/MDA in feet AMSL, not the parenthesized height above threshold. If only a height is supplied, use its stated datum elevation to obtain the altitude and cross-check it against threshold elevation. Use RADIO minimums only when the procedure authorizes them; simulator height above terrain is not automatically height above the runway. Read back both selector mode and value.
- Read both applicable descent and approach checklist sections. While flight is stable, complete independent preparation items before CDU troubleshooting: perform or verify the prescribed altimeter, pressurization, annunciator recall, minima, radio/course, sign/light, and autobrake checks, read their indications, then immediately call `mark_checklist` with the live identifiers and expected response. Verify accepted progress before moving to the next item. An unavailable VREF stays unmarked, not a reason to postpone other verified items; do not toggle an already-correct switch just to obtain a mark.
- Verify navigation identifiers and both courses against the chart. Decode selector detents from the documented mapping: a raw autobrake value is not necessarily the printed setting. Report unresolved inconsistencies without repeatedly cycling a functioning selector.

## Obtain valid landing performance

1. Read current gross weight and fuel from `takeoff-data` before typing a weight; do not copy a planning example or choose a plausible round number. Establish the installed CDU units, scale, and destination field from documentation. For a documented thousands-of-lb system, GROSS WT = gross kg × 2.2046 / 1,000, whereas ZFW = (gross kg − fuel kg) × 2.2046 / 1,000. For thousands of kg, omit the lb conversion. Round only to the field's displayed precision. Gross weight includes fuel; a calculated ZFW does not belong in APPROACH REF GROSS WT.
2. Read the page title and labels before each line-select key. Use the displayed INDEX and documented performance-initialization path if GW ENTRY INHIBIT requires a ZFW entry; MENU and its datalink branch are not a substitute for PERF INIT. Use the calculated current value in the field the documented path requires, then return to APPROACH REF and reconcile its gross weight with the aircraft reading. Do not invent unrelated route or performance inputs to unlock the page.
3. Make each entry atomic: interpret any message, clear the scratchpad using the documented controls, and read back an empty scratchpad before `cdu-type`. Typing appends to existing text; one CLR may only dismiss INVALID ENTRY and restore rejected text. After typing once, read back the exact calculated string before pressing the field's line-select key. If text is concatenated or unexpected, clear it rather than submitting it. DEL requests field deletion, not scratchpad erasure.
4. Read back the accepted destination weight and any error before selecting a flap/VREF choice. Verify the accepted landing flap/VREF field, not merely generated choices or scratchpad text. Set the prescribed VREF-based speed correction, verify MCP speed and actual IAS, and record the verified VREF item with `737-checklist`.
5. After each page/entry cycle, read flight instruments, FMA, and remaining approach distance; correct drift before another cycle. After one evidence-based correction still fails, stop repeating the same LSK/CLR sequence: call `report_issue` with the page, field, calculated units/scale, and observed rejection, then use a documented alternate entry path or approved performance source while flying a verified safe hold/vector as authorized. If already too close for preparation, discontinue the approach using the applicable procedure. A navigation-database date warning does not prove performance entry is impossible; reconcile the chart and receiver identification without changing navigation data in flight. Do not guess VREF, use an initial arrival speed as a landing speed, or proceed to final landing configuration without valid performance data.

## Execute the descent

- Choose the authorized intercept altitude from the chart and clearance, not an arbitrary round-number floor. Before leaving altitude hold, verify the descent mode, selected altitude, and selected rate; mode activation can synchronize targets, so read them again afterward. Recheck actual descent and IAS. If descent prevents deceleration, revise the rate or level safely within procedure limits and configure at the documented speeds; do not chase a lower altitude while fast and unconfigured. Continue with `737-approach`.
