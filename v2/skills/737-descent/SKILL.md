# Boeing 737 descent and approach preparation

## Prepare and record independent items

- Read actual altitude, IAS, vertical speed, configuration, FMA, and distance to the approach. Preserve functioning automation while preparing; an ALT HOLD label or selected altitude does not prove level flight at that target. Estimate minutes to the intercept as 60 times remaining NM divided by groundspeed in kt. If preparation will not finish in that distance, execute and verify an authorized level-off, vector, or hold within chart/clearance constraints rather than continuing toward the runway unprepared; level flight alone does not preserve the distance needed for preparation.
- Read the selected approach chart, live descent/approach checklists, landing continuation, and missed approach before intercept. Identify runway, ILS frequency/identifier, magnetic course, distance source, segment altitudes, minima datum, and missed-approach track/altitude. Different DME stations and threshold distance are not interchangeable; obtain the chart's required reference rather than assuming the ILS DME matches it.
- Set local QNH with the correct pressure units and verify the required altimeters and pressure-reference modes. Set pressurization landing altitude from the destination elevation, not the decision height; perform the prescribed annunciator recall and resolve actual warnings.
- For BARO minimums, enter the published DA/MDA in feet AMSL, not the parenthesized height above threshold. If only a height is supplied, use its stated datum elevation to obtain the altitude and cross-check it against threshold elevation. If `decision-height` rejects the DA/MDA as out of range, inspect the documented BARO control and call `report_issue` for an unavailable or incompatible control; never substitute a smaller threshold-relative height while BARO remains selected. Use RADIO minimums only when the procedure authorizes them; simulator height above terrain is not automatically height above the runway. Read back both selector mode and value. If no authorized minimums setup is available, protect the flight path and discontinue the approach rather than claim preparation complete.
- Read both applicable descent and approach checklist sections. While flight is stable, complete independent preparation items before CDU troubleshooting: perform or verify the prescribed altimeter, pressurization, annunciator recall, minima, radio/course, sign/light, and autobrake checks, read their indications, then immediately call `mark_checklist` with the live identifiers and expected response. Verify accepted progress before moving to the next item. An unavailable VREF stays unmarked, not a reason to postpone other verified items; do not toggle an already-correct switch just to obtain a mark.
- Verify navigation identifiers and both courses against the chart. Decode selector detents from the documented mapping: a raw autobrake value is not necessarily the printed setting. Report unresolved inconsistencies without repeatedly cycling a functioning selector.

## Obtain valid landing performance

1. Read current gross weight and fuel from `takeoff-data` before typing a weight; do not copy a planning example or choose a plausible round number. Establish the installed CDU units, scale, and destination field from documentation. For a documented thousands-of-lb system, GROSS WT = gross kg × 2.2046 / 1,000, whereas ZFW = (gross kg − fuel kg) × 2.2046 / 1,000. For thousands of kg, omit the lb conversion. Round only to the field's displayed precision. Gross weight includes fuel; a calculated ZFW does not belong in APPROACH REF GROSS WT.
2. Read the page title and labels before each line-select key. Use the displayed INDEX and documented performance-initialization path if GW ENTRY INHIBIT requires a ZFW entry; MENU and its datalink branch are not a substitute for PERF INIT. Enter calculated gross weight in a GW field or calculated zero-fuel weight in a ZFW field; a blank PERF INIT page does not make those values interchangeable. Do not invent unrelated route or performance inputs to unlock the page.
3. Make each entry atomic: interpret any message, clear the scratchpad using the documented controls, and read back an empty scratchpad before `cdu-type`. Typing appends to existing text; one CLR may only dismiss INVALID ENTRY and restore rejected text. After typing once, read back the exact calculated string before pressing the field's line-select key. If text is concatenated or unexpected, clear it rather than submitting it. DEL requests field deletion, not scratchpad erasure.
4. Return to APPROACH REF and read its accepted GROSS WT and any error. Convert that displayed gross weight back to kg and compare it with a fresh aircraft gross-weight reading, allowing only displayed rounding and measured fuel burn. Acceptance and populated VREF choices prove only that the CDU processed an entry, not that the weight is correct. If the values disagree, correct the weight and regenerate performance before using or marking VREF; never replace a rejected calculated weight with a plausible round number.
5. Select the planned flap/VREF using the documented CDU selection/entry sequence, then read the accepted FLAP/SPD pair. `--/---` means no selection: generated flap/VREF choices alone do not satisfy the VREF Enter item. Only after the selected pair and reconciled weight are verified, record that item with `737-checklist` and calculate the prescribed speed correction. Maintain the configuration-appropriate maneuver speed until `737-approach` calls for the landing-flap target; then verify MCP speed and actual IAS.
6. After each page/entry cycle, read flight instruments, FMA, and remaining approach distance; correct drift before another cycle. After one evidence-based correction still fails, stop repeating the same LSK/CLR sequence: call `report_issue` with the page, field, calculated units/scale, and observed rejection, then use a documented alternate entry path or approved performance source while flying a verified safe hold/vector as authorized. If already too close for preparation, discontinue the approach using the applicable procedure. A navigation-database date warning does not prove performance entry is impossible; reconcile the chart and receiver identification without changing navigation data in flight. Do not guess VREF, use an initial arrival speed as a landing speed, or proceed to final landing configuration without valid performance data.

## Execute the descent

- Choose the authorized intercept altitude from the chart and clearance, not an arbitrary round-number floor. Changing selected altitude while ALT HOLD is active does not initiate descent or move the captured level. Use the documented descent-mode command when descent is required, then read the active FMA, selected altitude, and selected rate again; mode activation can synchronize targets. Verify actual altitude change, vertical speed, and IAS rather than treating a verified set-altitude call as a descent. If descent prevents deceleration, revise the rate or level safely within procedure limits and configure at the documented speeds; do not chase a lower altitude while fast and unconfigured.
- Once the preparation items and selected performance are verified, read `737-approach` and the live landing section and execute its intercept/capture sequence. A solved CDU entry is a handoff to flight-path control, not completion of the arrival. Recheck distance and glide-slope geometry before the handoff; if the preparation delay has exhausted a safe intercept, execute the authorized reposition or missed approach instead of trying to salvage it with a late descent.
