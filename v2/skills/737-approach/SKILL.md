# Boeing 737 approach preparation and ILS capture

## Prepare while there is time

- Read actual position, altitude, IAS, vertical speed, configuration, active/armed FMA, selected targets, and alerts immediately. Preserve verified stable automation; the scenario description or phase label is not the current state. ALT HOLD holds altitude, not position: after each short CDU transaction, recheck flight state and distance/time to intercept using groundspeed. If preparation cannot finish with room to decelerate and configure, use a permitted vector, hold, or reposition while still stable instead of continuing inbound through repeated FMC retries.
- Read the assigned approach chart and aircraft landing, autoland, and missed-approach procedures using the available documentation tools. Brief runway, inbound course, intercept altitude, minima and their datum, missed-approach track/altitude, and landing distance. Keep each chart's DME station and threshold-distance reference distinct; do not apply one aid's profile altitudes to another receiver's distance.
- Verify local QNH against the actual altimeter settings. Tune and identify both ILS receivers and set both courses. Set the applicable minimums and seek an actual read-back; an unavailable minimums indication remains unverified, not confirmed by a successful setter.
- Obtain landing weight and the chosen flap setting's VREF from APPROACH REF. If blank, read current gross weight and fuel and use the documented INIT REF index/PERF INIT workflow in the displayed units. For thousands of pounds from kilogram readings, ZFW = (gross weight - fuel) × 2.2046 / 1000. Match the live field label: ZFW takes a single weight, not a weight/CG pair; GW/CRZ CG uses gross weight, not ZFW, and the documented CG format. Verify accepted gross weight and the landing reference; do not copy example weights or guess units.
- Before typing, read the scratchpad and clear messages and residual entries with the supported CLR actions; one CLR may only dismiss an error or remove one character. Confirm it is empty, type once, verify exactly the intended text, then press the field's live line-select key. After INVALID ENTRY, clear and inspect before a corrected retry; never append new text. If a correctly formatted, independently verified entry still fails, report it and use a documented weight/flap landing-speed table or permitted alternate source. Without a verified landing speed, remain outside final approach and reposition rather than waiting until the stabilization gate.
- Set and verify VREF plus the applicable procedure/wind correction on the MCP. Keep that target steady for the selected landing configuration; do not chase IAS or glide-slope oscillations by repeatedly raising and lowering selected speed. Read IAS trend, N1, thrust-lever position, and active A/T mode together to distinguish engine response lag from a control failure; a different landing flap selection requires its own verified reference speed.
- Finish and record each independently verified descent/approach item using `737-checklist` as it is completed, including landing altitude, navigation radios, and autobrake. An unresolved VREF or failed capture does not invalidate those observations. Conditional items require their actual trigger; temporary flaps 15 does not call for a flaps-15 landing inhibit. Report missing indication evidence rather than marking it to improve progress.

## Assess alerts before a busy final

- Read master caution/warning and the relevant system annunciators early. Identify the affected system, read the applicable non-normal procedure, and verify the individual fault indications before changing switches. For an air-conditioning caution, cross-check pack selectors, available pack/trip indications, bleed supply, duct pressure, and cabin altitude/rate; AUTO selectors and pressurized ducts alone do not prove the packs are operating.
- Do not cycle packs, bleeds, or unrelated systems experimentally, or reset an alert merely to obtain a clear indication. Use only the identified procedure's actions and recheck the underlying condition; acknowledgement is not fault correction. Keep flight-path reads between troubleshooting steps.
- If the interface cannot identify the fault, report the limitation and keep the condition unresolved. Establish whether the non-normal procedure permits landing and whether required systems remain available. If more assessment time is needed and prompt landing is not required, discontinue the approach using `737-go-around`; do not carry uncertain troubleshooting into low final. A caution alone is not an automatic go-around or proof that landing is prohibited.

## Capture without mode cycling

1. Establish the chart's permitted intercept altitude and a suitable heading, normally within 30° of the localizer course, with the glide slope above the aircraft. Complete preparation and begin scheduled deceleration/flap extension at verified maneuver speeds before intercept; do not remain clean at arrival speed while waiting for capture. If insufficient room remains, reposition rather than making a steep catch-up descent.
2. Verify receiver identity, signal validity, and the documented meaning of signed deviation readings before interpreting them. Cross-check geometry against the chart's threshold/localizer and named DME station, not the airport reference point; put coordinate-derived true bearings and magnetic courses on the same datum. Unresolved disagreement calls for safe repositioning and an issue report, not empirical sign-calibration turns while descending toward the runway.
3. Inspect actual active/armed FMA before pressing APP. Arm it once if needed; verify VOR/LOC and G/S arming separately from active capture. A button feedback flag or APP light is not capture evidence. Active VOR/LOC or G/S is capture evidence even when a button reports no change; assess actual deviations and path separately before deciding continuation is safe.
4. If a permitted descent before capture uses V/S, first read the active pitch mode and selected V/S. If V/S is already active, do not press its toggle again. Otherwise select it once and verify the mode, then set the intended descent target and read the window and actual response. A setter returning zero or a different target is unresolved even with `verified: true`; determine whether altitude capture or another mode made V/S unavailable rather than repeatedly sending larger descent targets.
5. Once G/S is active, stop V/S commands and preserve coupled guidance. Captured approach modes may reject V/S, HDG SEL, or ALT HOLD; changing selected targets does not cancel captured modes. Verify centered/trending deviations and actual descent. If continuation is unsafe, use the documented go-around/mode-exit procedure in `737-go-around`, not a climb command through captured G/S or a dive for the glide slope.
6. At observed glide slope alive, perform the prescribed gear DOWN/three-green, flap 15, both start switches CONT, and speedbrake ARM checks at safe configuration speeds. Verify actual states and the separate ARMED indication when available; lever selection does not substitute for a missing lamp. Continue with `737-landing` and record only evidenced items using `737-checklist`.
